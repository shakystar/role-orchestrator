# O-01: 관측 facade와 Langfuse 연동 기획

상태: 제안, 미구현. LangGraph 흐름 제어와 Go runtime 실행의 경계를 유지한다. 관측 처리는 독립 전송 경로이며 업무 워크플로의 완료 조건이 아니다.

```text
LangGraph ── 작업 요청 ── Go runtime ── codex-adapter
    │                        │               │
    └──────── 관측 이벤트 ───┴───────────────┘
                         ↓
                 공통 관측 계약/facade
                         ↓
              크기가 제한된 버퍼/로컬 보관
                         ↓
                  Langfuse 전송 어댑터
```

## 공개할 인터페이스와 소유권

| 경계 | 제안 계약 | 책임 |
| --- | --- | --- |
| 기록 | span 시작/종료, event, usage, flush | 호출자가 의미와 식별자를 제공; exporter가 전송 |
| 조회 | run/task 상태 요약, 지연·사용량·전송 완전성 | 읽기 전용, 조회 결과로 runtime 상태를 변경하지 않음 |
| 교체 | local/no-op/Langfuse exporter | 공급자 의존성은 어댑터 내부에 둠 |
| 실행 제어 | 기존 제출·완료 기록·SMS | Langfuse 가용성이나 도착 순서에 의존하지 않음 |

OpenTelemetry SDK·W3C trace context를 우선 조사한다. 범용 tracing 구현을 새로 만들지 않고 도메인 필드만 얇게 추가한다. Python SDK 콜백만으로 Go 내부 모델 호출이 보이지 않으므로 JSONL 경계의 전파와 Go 계측이 필요하다. SDK/OTLP 경로 중 채택할 전송 방식과 Langfuse 배치는 아직 결정하지 않았다.

## 식별자와 이벤트 초안

- `schema_version`, `event_id`, `run_id`, `task_id`, `role_ref`, `attempt_id`, `trace_id`, `span_id`, `parent_span_id`, `timestamp`, `duration`, `status`, `provenance`.
- 프로세스 재시작에도 run/task는 유지한다. 실제 새 실행은 새 attempt/span, 완료 기록 조회는 `receipt_cache_hit` 이벤트다. 캐시 조회에 모델 generation을 새로 만들지 않는다.
- 영속 graph checkpoint에는 필요한 correlation context를 저장한다. 이미 종료된 span을 재개하지 않는다. 재개된 실행 span과 기존 실행 사이의 parent/link 관계를 exporter가 보존하는지 검증한다.
- task 제안/접수/대기/실행/완료/실패/재심, 하네스 준비, 모델 완료, 사용량, 캐시 조회, exporter 오류를 구분한다. 이 이벤트 목록은 실행 상태의 원본이 아니다.
- 모델 스트리밍 사용량이 누적치인지 증분인지 확인한다. 누적 이벤트를 합산하지 않고 attempt별 최종 또는 단조 누적 값을 정규화한다.

## 시간·사용량·비용

벽시각은 상관관계 표시용, 각 프로세스의 지속 시간은 단조 시계로 측정한다. 서로 다른 프로세스의 단조 시각을 직접 빼지 않는다. 대기·하네스 준비·모델 실행 등 계측 가능한 구간만 표시하고 총합에 중첩 span을 중복 더하지 않는다. Python이 잰 RPC 왕복 시간을 전부 모델 지연으로 부르지 않는다.

입력/출력/캐시 토큰은 어댑터가 실제 보고하는 필드만 기록한다. 미지원·누락은 null/unknown과 이유로 남긴다. 비용 추정에는 모델명·가격표 버전·통화·계산 근거를 붙인다. 가격표가 없으면 비용도 unknown이다. Codex 구독 기반 실제 청구액, API 요율 환산치, 실제 모델 호출이 없는 결과 캐시는 서로 구분한다.

## 전송 실패와 용량 제한

업무 실행 스레드에서 원격 전송을 기다리지 않는다. 큐의 개수/바이트·디스크 보관량·보관 기간·재시도 횟수·종료 flush 시간을 제한한다. 값은 기준 부하 시험 뒤 정한다. 큐 포화 정책과 유실 수, 마지막 성공 전송, 미전송 수를 로컬에서 볼 수 있어야 한다. 무한 메모리 버퍼나 무제한 spool은 금지한다.

재전송 시 동일 event ID를 유지하고, 수신 측 중복 처리 보장을 확인한다. 보장되지 않는 경우 자체 집계에서 중복을 제거하고 전송 불완전성을 표시한다. 실행은 계속됐지만 관측이 유실될 수 있다는 한계를 숨기지 않는다. 예산 집행과 완료 판정은 비동기 Langfuse 집계가 아니라 로컬 영속 실행/사용량 기록을 기준으로 한다. 알 수 없는 사용량에 적용할 보수적인 예산 정책도 별도 결정한다.

프롬프트·응답·근거 원문은 기본 전송 대상에서 제외한다. 식별자·길이·해시·상태·수치부터 계측한다. 원문 수집 범위와 보관 정책은 실제 필요가 생기면 결정한다.

## 최소 수용 시험

| 시험 | 기대 결과 |
| --- | --- |
| 기존 실제 모델 4작업 | runtime 완료 기록 4건과 관측상의 고유 모델 실행 4건 일치 |
| 별도 프로세스 재개 | 동일 run 아래 연결되며 종료된 span을 덮어쓰지 않음 |
| 완료 결과 재조회 | cache-hit만 추가, 모델 호출·토큰·모델 비용 증가 없음 |
| 사용량 누락/누적 이벤트 | unknown과 실제 0 구별, 누적치 중복 집계 없음 |
| Langfuse 단절·지연·큐 포화 | 업무 실행을 exporter가 막지 않음; 한도와 유실이 드러남 |
| 재전송·중복·순서 변경 | 집계 중복 및 완료 상태 역행 방지 |
| 계측 on/off 비교 | 같은 fixture 부하의 지연·메모리 비교; 실제 모델 지연과 분리 |

현재 시험은 기획이며 시행 전이다. 배치 방식은 local self-host / Cloud 중 선택할 과제로 남긴다. 거대한 관측 UI나 별도 마이크로서비스는 이 최소 검증의 전제가 아니다.
