## 개발 인계

acl-023 → acl-024 → acl-025 → acl-024 → 기획팀. 같은 건 ID 아래 acl-024가 근거·초안 버전과 작성 참여자 목록을 고정한다. acl-025는 검토자 ID·검토 대상 버전·이해충돌 여부·의견 ID를 남긴다. acl-024는 의견별 반영 여부와 남은 이견을 보존하고 단계별 영수증을 연결한다.

- **W-ACL · agent-collaboration-lab** 팀 계약과 신규 3인만 추가한다. 제공 명부 290562c에서 acl-001~022와 acl-023~025는 중복되지 않는다. 적용할 설정에서도 팀 ID·ACL ID 충돌이 없고 기존 22명의 값·권한이 그대로인지 차이를 대조한다.
- **W-RUNTIME · role-orchestrator** 의뢰와 신호의 진입 조건을 구분하고 W-ACL 명부로 인계 순서와 독립성 검사를 적용한다. 기존 배정·영수증 참조를 재사용하고 role-runtime·codex-adapter의 실행·모델 전달은 유지한다.
- **W-ARTIFACT · agent-eval** 공통 입출력, 두 사례의 입력·통과·실패 조건과 W-ACL·W-RUNTIME 검증 기록을 정리한다. 기존 규격으로 표현 가능하면 문서와 테스트만 추가한다.
